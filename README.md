# Сервис коротких ссылок

Локальный Java-сервис сокращает HTTP(S)-адреса, ограничивает переходы и автоматически удаляет ссылки по истечении срока. Управление выполняется в консоли. Ссылки открываются в браузере на том же компьютере, пока сервис запущен.

## Запуск

Установите JDK 21 и Maven 3.9. При первой сборке Maven скачает плагины и JUnit для тестов. Для запуска собранного JAR достаточно JDK.

```powershell
mvn verify
java -jar target/url-shortener-1.0.0.jar
```

В Windows после сборки можно дважды щёлкнуть **Start Shortener.cmd**. Если порт 8080 занят, выберите свободный порт в `config.properties`.

## Первый запуск

1. В консоли приложения введите `short https://example.com/ 2`.
2. Сохраните UUID, который выдаст приложение. Он позволяет позже управлять своими ссылками через `use <UUID>`. Храните его отдельно от коротких ссылок.
3. Вставьте выданную короткую ссылку в эту же консоль и нажмите Enter. Браузер откроет исходный адрес через локальный редирект. Ссылку также можно открыть прямо в браузере.
4. После двух переходов ссылка станет недоступной. Владелец увидит уведомление в консоли.
5. Введите `exit` для сохранения и завершения программы.

Чтобы проверить двух пользователей, создайте ссылку, запомните её UUID и код. Затем введите `new` и снова выполните `short` с тем же исходным URL. Получите другой UUID и код. Попытка удалить первую ссылку во втором сеансе будет отклонена.

## Команды

| Команда | Действие |
|---|---|
| `help` | Показать команды и пример |
| `short <URL> [лимит]` | Создать ссылку, при необходимости выдать UUID |
| `open <код или короткая ссылка>` | Открыть ссылку в браузере. Короткую ссылку или код можно ввести отдельно |
| `list` | Показать свои активные ссылки, лимиты, число переходов и срок |
| `limit <код> <лимит>` | Изменить лимит активной ссылки. Новый лимит должен быть больше числа уже учтённых переходов |
| `target <код> <URL>` | Изменить исходный адрес активной ссылки |
| `delete <код>` | Удалить свою ссылку |
| `id` | Показать текущий UUID |
| `use <UUID>` | Выбрать существующего пользователя |
| `new` | Выйти из текущего сеанса. Следующая команда `short` создаст нового пользователя |
| `exit` | Сохранить данные и завершить работу |

Лимит считается по запросам GET к короткой ссылке. Последний разрешённый запрос получает HTTP 302, следующий получает HTTP 410. Ответы содержат `Cache-Control: no-store`. Для удаления и редактирования сервис проверяет UUID владельца. Уведомления показываются активному владельцу на очередной фоновой проверке или после его следующего входа через `use`.

## Конфигурация и хранение

| Параметр `config.properties` | Значение по умолчанию |
|---|---|
| `port` | 8080 |
| `ttl` | `PT24H`, сутки с момента создания |
| `cleanupInterval` | `PT1S`, фоновая проверка раз в секунду |
| `noticeRetention` | `P7D`, семь суток для причин блокировки и уведомлений |
| `defaultLimit` | 10 переходов |
| `maxLimit` | 10 000 переходов |

Настройки TTL применяются к новым ссылкам. Для проверки истечения можете скопировать конфигурацию, указать в копии `ttl=PT5S` и запустить приложение с отдельной папкой данных:

```powershell
java -jar target/url-shortener-1.0.0.jar config-test.properties data/test
```

Состояние сохраняется при штатном выходе в `data/links.db` через временный файл и замену. После запуска выберите прежний UUID командой `use`. При аварийном завершении изменения текущего сеанса могут быть потеряны. Просроченные ссылки проверяются также при обращении, поэтому задержка фоновой проверки не продлевает TTL.

## Архитектура

- `shortener.core.LinkService` управляет ссылками, UUID, сроками, правами и уведомлениями. Переходы и изменения состояния синхронизированы. Случайный 12-символьный код проверяется по всем ранее выданным кодам.
- `shortener.infra` читает конфигурацию, сохраняет состояние и обслуживает HTTP-редиректы на `127.0.0.1`.
- `shortener.ui` связывает модули и ведёт диалог с пользователем. Браузер открывается через `Desktop.browse`.

## Тестирование

```powershell
mvn test
mvn verify
```

Модульные тесты проверяют уникальность, права, границы TTL, лимиты и параллельные переходы. Интеграционные тесты проверяют локальный HTTP-сервер, консоль, конфигурацию и восстановление сохранённого состояния. GitHub Actions выполняет сборку и тесты при push и pull request. Компиляция использует `-Xlint:all -Werror`, форматирование задано в `.editorconfig`.
